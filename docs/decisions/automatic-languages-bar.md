# Decision: automatic languages bar on content pages

- **Status**: Accepted (2026-09-10) — extends `static-llm-translation.md`
- **Scope**: `wikibase.ronzz.org` — the static-copy translation model's
  language switcher (page content only; entity terms stay Wikibase-native)
- **Decider**: Rongzhou (`ron@ronzz.org`)

## Context

The static-copy model (`static-llm-translation.md`, Aug 19 2026) links a
page's `/fr` and `/eo` copies with a `{{Languages}}` bar that editors add by
hand. In practice only a handful of pages carry the bar; readers cannot
discover a translation from the source page unless an editor remembered to
add it, and every newly created page is missing it (the Add\* flows create
`Person:`/`Source:`/`Collective:`/`Software:` pages whose skeletons never
included it).

`Template:Languages` is unconditional (ParserFunctions is not installed), so
the bar always shows all three slots — a missing copy is a red link, a
deliberate "create this translation" invitation.

## Decision

**The languages bar is included by default on every content page.** A small
standalone extension (`extensions/LanguageBar/`) prepends the bar at render
time via the `OutputPageBeforeHTML` hook on article views in an allow-listed
set of namespaces (Main, Help, Cheatsheets, HowItWorks, FOSS, Person, Source,
Collective, Software). `Template:Languages` becomes a thin wrapper around the
extension's `{{#languagebar:}}` parser function, so the automatic bar and an
explicit template call share one markup definition.

The hook skips a page whose HTML already renders a bar (an explicit
`{{Languages}}`), a `/fr`/`/eo` translation copy (which carries the
`{{Translation}}` banner), and diffs. Entity (`Item:`/`Property:`),
`Template:`, `Category:`, `MediaWiki:`, `Special:`, talk, `Forum:` and the
gated `RonzzIT:`/`RonzzInt:` namespaces are excluded.

## Why

1. **The bar is a reader-facing navigation aid, not page content** — every
   content page should offer it, like the skin's title/tabs; leaving it to
   editors guarantees it is absent where it matters.
2. **The static-copy model depends on discoverability** — a translation that
   readers cannot find from the source page does not exist for them.
3. **Server-side injection covers existing AND future pages** — the Add\*
   flows' auto-created pages get the bar with no skeleton change, and no bulk
   wikitext edit is needed.
4. **One markup definition** — the parser function keeps `Template:Languages`
   (still used on the gated `RonzzIT:` pages) rendering identically to the
   injected bar.

## Consequences

- **Gained**: the bar is present everywhere it makes sense, including pages
  created after the change; no per-page editor action; one markup source.
- **Given up**: the "bar only where a translation exists" curation. The bar
  is now unconditional (red links included) — accepted, because the red link
  is the translation invitation and ParserFunctions is not installed.
- **Risk — duplicate bars**: mitigated by the hook's HTML marker check
  (skips when `languages-bar` is already present) and the `/fr`/`/eo` +
  `{{Translation}}`-banner skips. Regression-tested in
  `tests/e2e/run_languagebar_e2e.py`.
- **Risk — namespace drift**: the allow-list is instance config
  (`$wgLanguageBarNamespaces`); a new content namespace must be added to it.
  The extension default (`$wgContentNamespaces` + Help) is the fallback.
- **Entity pages untouched**: `Item:`/`Property:` pages are generated by
  Wikibase, not wikitext; their multilingual content is native (ULS), so the
  bar does not apply.

## Alternatives considered

| Option | Assessment |
|--------|-----------|
| **A.** Automatic `OutputPageBeforeHTML` injection + parser-function single source (chosen) | Accepted — covers existing and future pages, no wikitext churn, one markup definition |
| **B.** Bot mass-edit every page's wikitext to add `{{Languages}}` | Rejected — does not cover future pages, adds markup to thousands of pages, entity pages cannot take a template |
| **C.** Skin change | Rejected — forks an upstream skin (`Vector`/`Timeless`), against the repo's "no forks" rule |
| **D.** Leave the manual per-page bar | Rejected — the status quo: most pages (and every auto-created page) lack it |
