# AGENTS.md — dev Agent Instructions

## Summary

Local dev/CI stack for ronzz-wikibase: a reference-deployment wikibase-docker
(WBS) instance used to validate the integration layer (extension loading,
seed, D1 importers, E2E + XSS suites) before touching production.

## Purpose and Expected Behavior

- **Never develop directly on the production server** — this stack (or CI's
  ephemeral stack) is the sanctioned integration surface.
- Architecture pinned to production-equivalent versions: MediaWiki 1.46,
  WDQS 0.3.156, MariaDB 10.11. **WDQS/Blazegraph is ON** — for CI (16 GB
  runners) or machines with RAM to spare (~2.5 GiB total).
- The WBS image requires a configuration volume at `/config` (host dir
  `dev/config/`). On first boot it generates `InstanceSettings.php` +
  `LocalSettings.php` there; the generated `LocalSettings.php` loads
  `dev/config/Extensions.php`, which enables our two extensions and — once
  the seed has emitted it — the seed config map
  (`dev/config/ronzz-wikibase-config.php`). A `jobrunner` container shares
  the config volume (the WBS image requires it).
- Extensions are bind-mounted read-only from the repo — code edits are picked
  up by `docker compose restart wikibase` (no image rebuild).

## Constraints and Invariants

- `dev/config/` is mostly generated by the image (gitignored except
  `Extensions.php`); `mkdir -p dev/config` before `up -d` so the mount is
  writable by your user.
- The seed writes the config map into `dev/config/ronzz-wikibase-config.php`
  (gitignored, generated).
- **WDQS updater quirk (0.3.156)**: on a fresh instance, backoff polling can
  skip entities created while it is mid-catch-up. Start the updater only
  **after** all entities exist; the SPARQL acceptance check retries with
  `--sparql-wait` (see repo root AGENTS.md — do not re-debug).
- RAM: the full stack (incl. Blazegraph) needs ~2.5 GiB. On a tight machine,
  run only `wikibase` + `mysql` (drop the `wdqs*` services, remove the
  `wdqs-updater` dependency) and skip the SPARQL check.
- Dev-only CI credentials (`CIAdmin` / `ci-admin-pass-2026`) are ephemeral
  runner values — never production secrets.

## Input/Output Expectations

- **Input**: `dev/docker-compose.ci.yml` (stack), `dev/config/Extensions.php`
  (extension loading).
- **Output**: a running wiki at `http://127.0.0.1:8082` (api.php), WDQS at
  `http://127.0.0.1:9999/bigdata/namespace/wdq/sparql`, and the seed-emitted
  config map `dev/config/ronzz-wikibase-config.php`.
- Full quick-start sequence (up → wait → D1 importers → seed → restart →
  updater → E2E/XSS/page flows) is in `dev/README.md`.

## Domain-Specific Rules for Agents

- Prefer **CI over local stack runs** on resource-tight machines: edit →
  local unit tests → push → CI gate (`gh workflow run ci.yml` for ad-hoc
  full validation). Only run the stack locally when interactive debugging is
  needed.
- A clean reset is `docker compose -f dev/docker-compose.ci.yml down -v` —
  keeps nothing.
- Do not commit generated files under `dev/config/` or `seed/generated/`
  (gitignored).
- The extensions are read-only bind mounts — editing them requires a
  `docker compose restart wikibase`, not a rebuild.
